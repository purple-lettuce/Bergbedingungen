# 🔄 Entwicklungsworkflow

Dieses Dokument beschreibt die verbindlichen Arbeitsabläufe für Änderungen an Bergbedingungen.

Ziel ist es, dass Code, Dokumentation und Roadmap jederzeit synchron bleiben.

---

# Grundsatz

Die Dokumentation ist die Quelle der Wahrheit.

Codeänderungen müssen immer gegen die aktuelle Dokumentation geprüft werden.

---

# Workflow für jedes Arbeitspaket

Nach Abschluss eines Arbeitspakets müssen folgende Schritte durchgeführt werden:

## 1. ROADMAP prüfen

Prüfen:

- Wurde ein geplanter Punkt abgeschlossen?
- Muss ein Status aktualisiert werden?
- Müssen neue Erkenntnisse ergänzt werden?

Falls ja:

- Fortschritt aktualisieren
- Checklisten abhaken
- Status anpassen

---

## 2. DATENQUELLEN prüfen

Prüfen:

- Wurde eine neue Datenquelle eingebunden?
- Wurden neue Erkenntnisse gewonnen?
- Haben sich APIs oder Datenfelder geändert?

Falls ja:

- DATENQUELLEN.md aktualisieren

---

## 3. IDEENSAMMLUNG prüfen

Prüfen:

- Wurde eine Idee umgesetzt?
- Ist eine Idee nun konkret genug für die Roadmap?

Falls ja:

- Idee entfernen oder verschieben
- In ROADMAP übernehmen

---

## 4. README prüfen

Prüfen:

- Wurde eine sichtbare Funktion ergänzt?
- Muss die Projektbeschreibung angepasst werden?

Falls ja:

- README aktualisieren

---

## 5. Pull Request Abschlusskontrolle

Vor dem Merge prüfen:

- Code funktioniert
- Dokumentation aktuell
- Roadmap aktuell
- README aktuell

---

# Definition of Done

Ein Arbeitspaket gilt erst als abgeschlossen wenn:

✅ Code implementiert

✅ Tests erfolgreich

✅ ROADMAP aktualisiert

✅ Dokumentation aktualisiert

✅ README geprüft

✅ Pull Request gemerged
